# fuzz/ — coverage-guided fuzzing of the critical sections (REQ-r10)

Design of record: `docs/audit/REQ-r10-fuzzing-design-2026-11-20.md`, ruling and conditions
`docs/audit/RESP-r10-fuzzing-design-2026-11-20.md` (C-R10-1 … C-R10-7, C-R10-F in `CONDITIONS.md`).

**Outside the TCB.** This is a standalone crate: `core/Cargo.toml`, `core/Cargo.lock` and
`core/PROVENANCE.md` are untouched by anything here; nothing built here ships or is measured. The
harness uses the public API of `signer-core` (with its host-side `std` feature, as the vector suite
does) and the vector suite's own fixtures (`core/tests/common/mod.rs`, included by path).

## Layout

| Path | What |
|---|---|
| `src/targets.rs` | one body per target, `fn(&[u8])`; every assertion is an oracle and names itself (`C-R10-n`, `C-R9-A`, …) |
| `src/structured.rs`, `src/gen.rs` | phase 2 pass (i): the scripted targets (`state_ops`, `headers`, `work_add`) and their generators (a regtest miner on the fixture checkpoint, the regtest/signet fixture states, the reference 256-bit adder) |
| `src/policy.rs` | phase 2 pass (ii): `classify` (F7) and `judge` (F8) over a scripted PSBT generator with one host-asserted lie on demand; the harness's own reading of I1–I4, §1.4 and C-R10-4 |
| `src/dispatch.rs` | phase 2 pass (iii): `dispatch` (F10) — `rcore` under `nosgx,test-init` through the real `rcore_call`, scripted op sequences and raw requests; the oracle is `ops.rs`'s marshalling order with `signer-core`'s own decisions on the state read back from the nosgx blob, plus the model of the volatile session (boot-arm, high-water mark, TPM nonce/proof) and of the host's TPM; `TEE_FUZZ_TRACE=1` prints every call's verdict |
| `src/seeds.rs` | the honest objects the oracles are calibrated on (throwaway test keys only) |
| `fuzz_targets/*.rs` | the libFuzzer binaries, one line each, calling the bodies |
| `tests/replay.rs` | **the CI gate**: replays `seeds/` + `corpus/` + `regressions/` on stable 1.92.0 (must pass), asserts every open `findings/` reproducer still fires, calibrates the oracles on the honest set, holds the C-R10-1 re-tag vectors; also the seed writer |
| `seeds/<target>/` | hand-written seeds with descriptive names, regenerated by `write_seeds` (honest objects incl. the variants that reach every encoding arm, the vectors' bytes, negative/re-tagged inputs that must be refused, `validate`-refused mandates) |
| `corpus/<target>/` | the fuzzer-grown corpus (hash names); a run writes here — minimise (`cargo +nightly fuzz cmin`) and review before committing |
| `regressions/<target>/` | resolved findings' reproducers — pass forever |
| `findings/<target>/` | **open** findings: reproducer + `FINDING.md` entry; moved to `regressions/` with the RESP reference once resolved |
| `dict/<target>.dict` | magic constants (versions, tags, `TPM_GENERATED`, …) |
| `examples/explain.rs` | `cargo run --no-default-features --example explain -- <target> <file>`: what an input decodes to, then the oracle |
| `run.sh` | a discovery run with the pinned nightly and the per-target limits |

## Running

```bash
cd fuzz
cargo test --no-default-features                 # the replay gate (stable; what CI runs)
./run.sh <target> [seconds=3600] [jobs=4]        # discovery (nightly-2026-06-21 via cargo +toolchain; cargo-fuzz 0.13.2)
FUZZ_IGNORE_CRASHES=1 ./run.sh <target> 3600 4   # keep exploring past a known open finding (fork mode)
cargo +nightly-2026-06-21 fuzz cmin --fuzz-dir . <target> corpus/<target>   # minimise the grown corpus before committing it
TEE_FUZZ_SEEDS_OUT=seeds cargo test --no-default-features --test replay -- --ignored write_seeds   # regenerate seeds/
./injected-defects.sh                            # C-R10-7(b): every reverted core guard must turn the gate red (restores core/)
./coverage.sh <target>                           # C-R10-7(a): functions of core/src the inputs reach (seeds + corpus + regressions; reports in coverage/<target>/)
```

Targets: `proto_decode` `mandate_decode` `mandate_compare` `message_decode` `state_decode`
`tpm_attest` `receipt_decode` `encoding_dec` `bip39` `cross_type` (REQ-r10 §2, F1–F5, F9, C-R10-1); phase 2 pass (i):
`state_ops` (F4: scripted 8-byte step records over the honest state — every `apply_*` entrypoint, the timelock and
frozen-path rules as the harness's own model), `headers` (F6: raw and scripted regtest sessions against a model
chain, the real signet chain with a mutation, the no-wrap boundary at the call site), `work_add` (C-R10-6 directly:
`add_work_le` against a reference adder). Inputs are scripted, not `arbitrary`-driven, so every seed is hand-written
and every injected defect has a deterministic reproducer. Pass (ii): `classify` (F7: raw PSBTs; the scripted build with
every host-asserted lie and the exact refusal each must draw; the differential "the host never decides" — no lie turns
a refusal into a different acceptance) and `judge` (F8: state × mandate knobs × PSBT × witness token; the accept
invariants and the window charge recomputed by the harness, the liveness refusals in order, `disarms` exactly on the
verified seq-behind token — both directions). Pass (iii): `dispatch` (F10: the enclave's shell `rcore` on the host — `nosgx`
stand-ins for the SDK, `test-init` for a known seed — called through the exported `rcore_call`; mode 0 feeds one raw
request to one op, mode 1 scripts up to 16 steps over a live blob — every op, a reload, older and mutated blobs, the
host's TPM depositing honest or lying proofs; the oracle for each call is `ops.rs`'s order of gates with the
decisions of `signer-core`'s own functions on the state read back from the nosgx blob: the blob changes only
through a `Fresh` op and exactly as the core says, a TPM-bound state refuses every `Fresh` op without the right
proof, `SIGN` signs only the judged bytes on the charged blob, a reload is unarmed, an older blob is behind the
session mark; the response bytes are predicted exactly, signatures included — RFC 6979).

Limits (`run.sh`): `-max_len` from the `proto` bound the type lives under, `-malloc_limit_mb` **below**
that bound (an untrusted length that drives an allocation is itself a V2 DoS finding), `-timeout=10`,
`-rss_limit_mb=1024`. Runs happen on the dev laptop only — never on the shared build box or the node
(REQ-r10 §4); fuzzing is host-side `std` code and needs no SGX.

## A finding

1. The oracle's panic names itself; libFuzzer writes `artifacts/<target>/crash-*`.
2. `explain` it; copy the reproducer to `findings/<target>/F-<date>-<n>-<what>` and write the entry in
   `findings/<target>/FINDING.md` (what fires, against which text of the design of record, the install-path
   reading, impact as understood, a proposal if any). Commit — before any fix.
3. Report to the auditor. A fix in `core/` or `rcore` is an impl REQ (IMPL-PASS before merge, a new MRENCLAVE
   rides the next ceremony build and is labelled until then). An oracle refinement is the auditor's ruling.
4. When the reproducer stops firing, the replay test says so; move it to `regressions/` and reference the RESP.

## Toolchains

The repo pins `1.92.0` (`rust-toolchain.toml`) for every gate; the replay test runs on it. The libFuzzer
build needs a nightly: `run.sh` passes `+nightly-2026-06-21` explicitly, so the root pin is not disturbed
and nothing nightly reaches a gate. `cargo install cargo-fuzz --locked --version 0.13.2`; for `coverage.sh`:
`rustup component add llvm-tools-preview --toolchain nightly-2026-06-21` and `cargo install rustfilt --locked`
(readable symbol names; without it the report stays mangled).
