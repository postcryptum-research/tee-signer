## 3. The gate

`cargo test --no-default-features` in `fuzz/` on 1.92.0 (CI job `fuzz-replay`): replays `seeds/` + `corpus/` +
`regressions/` through the bodies (every input must pass), asserts every `findings/` reproducer **still fires**
(an expected-fail class: a quiet fix turns the gate red until the file is moved to `regressions/` with the RESP
reference), calibrates the oracles on the honest set, and runs the re-tag vectors. Inputs replayed at this
commit: **2109** over ten targets (324 seeds, 1783 corpus files, 2 regressions, 4 open-finding reproducers), **3.5 s** on the laptop once built (debug profile).

## 5. Findings — the path exercised

### 5.1 F-2026-11-20-01 — `compare`: a changed checkpoint at the same height is "tightening" (C-R10-5) — **DEFECT (auditor), open**

The oracle fired after **82 executions** of the first 45-second run. Two mandates differing only in
`checkpoint.time`, `.bits`, one byte of `.hash`, `.period_start_time` or `.period_bits` (same height) classify as
`Tightening` in both directions:
`compare` tests `new.checkpoint.height >= installed.checkpoint.height` only. Against `POLICY.md §5` ("moved
forward"; "not provably tightening ⇒ loosening"). The auditor ruled the same day: **defect, two legs** — (1) the
compare rule (fix: `new.checkpoint == installed.checkpoint || new.checkpoint.height > installed.checkpoint.height`,
approved), (2) the install path's `known` check (`state.rs`, `PolicyUpdate` arm) matches hash + height only and
must validate `time`/`bits`/`period_bits`/`period_start_time` against the enclave's own state, fail-closed
(`PolicyInvalid` when not derivable). Severity medium (a weakening of the V5 timelock control scoped to
checkpoint content; chain-view impact gated on a frozen chain). Full text: `fuzz/findings/mandate_compare/FINDING.md`.
**Handling:** reproducers committed before any fix; the oracle unchanged; discovery continued in fork mode past
it — the one-hour run produced 560 more crashes, every one of them this class (§4), nothing else. **Next:** the fix as its own impl REQ on a branch with the auditor's break-tests (`REQ-r10-f01-checkpoint-impl`),
IMPL-PASS, a new MRENCLAVE with the next ceremony build; nothing deploys without the owner's GO.

### 5.2 `compare` is not reflexive on an *invalid* mandate — a precondition, not a finding

Two fuzzer inputs (`regressions/mandate_decode/REG-2026-11-20-01-invalid-dup-labels-{a,b}`): mandates with
`validate() == Err(AccountPath)` and 32 trusted entries sharing an empty label, on which `compare(m, m) ==
Loosening` — `compare` matches trusted entries by the first entry with the label. The enclave reaches `compare`
only after `validate` (which refuses duplicated labels), so C-R10-5 is asserted over **valid** mandates in both
targets; decoding and `validate` stay total on every input. Reported to the auditor as an observation on the
contract (compare has no defence of its own against duplicates), with the offer to make it a third leg of the
F-01 fix if wanted.

## 8. Deviations from the design REQ, stated

- **Open findings live in `fuzz/findings/`**, asserted to still fire, and move to `regressions/` on resolution
  (REQ §3 said "committed to `fuzz/regressions/` before the fix"). Reason: the gate stays green with the finding
  visible, and a quiet fix turns it red. Approved by the auditor 2026-11-20.
- **`seeds/` split from `corpus/`**: hand-written seeds keep descriptive names and are regenerated; the grown
  corpus is minimised with `cmin` (which renames to hashes).
- **C-R10-5 scoped to valid mandates** (§5.2) — endorsed by the auditor 2026-11-20 as the contract (not a weakening), with the requirement that `State::new_at_init` enforce "the installed mandate is always validated" at the write site — carried into the F-01 fix REQ.
- **`coverage.sh` does not replay `findings/`** (§6a) — the design said "corpus + regressions + findings"; an aborting reproducer loses the profile of the whole run.
- **`mandate_compare` has no C-R10-2 assertion of its own**: the same decoder is held to canonicality exhaustively in `mandate_decode`; the pair target spends its executions on `compare`.
- `bip39`: the REQ said "a mnemonic with a bad checksum is refused"; the core API has no mnemonic *import*
  (`seed(&str)` is PBKDF2 over any string; the enclave only generates), so the oracle is determinism + list
  membership + totality. Honest label, not a gap: there is no import path to fuzz.
- `fuzz-smoke` runs on pushes to `main` as well as PRs (this repository works by direct pushes).
