**R3 PoW clock — PASS.** A block clock from the owner-pinned checkpoint is the only honest clock (no trusted time on SGX1); forge-resistant (144 real-PoW blocks/window on mainnet), withholding is DoS-only (can't LOOSEN), maxReorg-freeze is fail-closed. Host-time alternative correctly rejected (weaker + needs a monotonic counter SGX1 lacks).

**R4 Classification — PASS, reasoning SHARPENED.** The own-index-bound-raised-by-use is NOT a loosening vector, and the reason is stronger than "all are the wallet's own keys": classification is a cryptographic derivation MATCH (`scriptPubKey == P2WPKH(derived_pubkey[i])`) — the bound only sets search depth; a foreign address matches NO derived key at ANY index, so widening it can never admit a non-wallet output; raising it only moves value to a key the enclave itself derives (merchant recovers it). Conditions: (a) bound search bounded by `ownIndexGap`≤100 + maxInputs/Outputs; (b) `own_index_bound` monotonic, only within the sealed account path; (c) OP_RETURN handling explicit (non-zero-value or opReturn=none ⇒ refuse).

**R5 Net outflow & fee — PASS, but the stated justification is INCOMPLETE; correcting (load-bearing).** "fee abs bound covers the dust case" is NOT why it's safe — `maxFeeAbs` only bounds fee PER-TX. The load-bearing fact: net outflow = Σown_in − Σown_out ALGEBRAICALLY INCLUDES the fee (= non-own-outputs + fee), AND every class — trusted INCLUDED (POLICY §3: "a trusted output counts toward the entry's caps AND toward `limits.window.maxOutflow`") — counts toward `window.maxOutflow`. So total fee-drain per window is bounded by `window.maxOutflow`, not by `maxFeeAbs` (and this is exactly carried-F2). ⇒ `maxFeeRate`-relative-to-outflow is NOT needed. Named residual (bounded, V1-only, detectable): an attacker can (i) burn up to ~`window.maxOutflow` in FEES/window (a real loss even though payments land in trusted cold) and (ii) exhaust the window budget → DoS of legit payouts. Optional `maxFeePerWindow` caps fee-burn below outflow; NOT required (right-size — the window cap already bounds the loss). Condition: state the fee-∈-net-outflow identity in POLICY so the bound is auditable + add the many-trusted-max-fee→CAP_WINDOW vector (R12).

**R6 Update protocol — PASS.** Hunted for a tightening-labeled change that enables theft — none. Everything that could widen (raise caps, add/alter a trusted dest, lower `timelockBlocks`, change `witnessPubKey`, RotateOwner) is loosening and waits the INSTALLED mandate's timelock ⇒ shortening the timelock is itself timelocked. V1 can't submit a valid update (needs owner sig); V5 can only tighten (DoS) or submit a loosening the owner cancels with the recovery key in time; Recover (recovery key) correctly immediate. ⛔CONDITION (IMPL bar): the tightening classifier must FAIL TOWARD LOOSENING — field-by-field on the CANONICAL decoded mandate; if ANY field is not provably tightening (incl. unknown/absent), the whole update is loosening. Never default an ambiguous field to tightening.

**R7 State order — PASS.** commit→seal→hand→sign→receipt is fail-safe (crash between seal and sign = budget charged, no signature; the opposite could emit a signature the state forgot → double-spend on reload). Receipt-after-sig (carries txid) is fine — it's an audit artifact, not a gate. Condition: on reload the host-supplied sealed blob is UNTRUSTED input (verify seal/MAC); a validly-sealed-but-older blob is what the freshness witness (R13) catches.

**R8 Recovery blob — PASS.** Ephemeral-P256-ECDH+HKDF-SHA256+AES-256-GCM, AAD=fingerprint‖xpub, once at init, no other path — correct. "Once" is right: a re-export would be a SECOND path by which the seed leaves (I12 would no longer be "once") = more surface on the top secret; a recovery-key rotation = new wallet (sweep). AAD binds the blob to THIS wallet (no cross-wallet replay). Conditions: (a) ephemeral key from in-enclave RDRAND, zeroized; (b) GCM-nonce uniqueness structural (fresh ephemeral ⇒ fresh HKDF ⇒ safe — state it); (c) I12 mutation-tested: a vector proving NO ecall but init yields the seed or a function of it beyond sigs/pubkeys.

**R13 Freshness witness — PASS, residual named precisely.** Two-check (tip within maxTipLag of best AND last_seen_seq ≤ own seq) is sound: after rollback own seq drops, the witness's current token carries a HIGHER last_seen_seq ⇒ check-2 fails; a replayed OLD token has an old tip ⇒ once the chain moves past maxTipLag, check-1 fails. PRECISE residual: within maxTipLag blocks of the rolled-back point, an attacker holding a token with last_seen_seq ≤ rolled-back-seq AND tip still within maxTipLag passes both checks once ⇒ maxTipLag DIRECTLY bounds the residual window; set it as small as the witness cadence allows (POLICY 1–144; state the chosen value's exposure per network).
